Developer guide · v1.6.0

Build, extend and publish Universal Presence

This guide explains the whole project: how Windows media sessions become a Discord activity, how to add plugins, profiles, localization, artwork rules and game mode, and how to ship a release. The app is .NET 8 WinForms, has no NuGet dependencies and runs entirely on the user's PC.

Quick start

1

Clone and build

Use the .NET 8 SDK. The project targets net8.0-windows10.0.19041.0 and uses Windows 10/11 APIs.

git clone https://github.com/itsmilespr/UniversalPresence.git
cd UniversalPresence
dotnet build -c Debug
2

Run in test mode

Test mode prints every SMTC session without talking to Discord.

./bin/Debug/net8.0-windows10.0.19041.0/UniversalPresence.exe --test --dry-run --seconds 20
3

Open settings

Settings are optional. The tray icon opens them, or use --settings.

UniversalPresence.exe --settings
No whitelists. The app never filters by player name. Every session Windows exposes through SMTC is eligible, unless the user explicitly adds it to the ignored list.

Architecture

The app is deliberately small and has no external dependencies. The main flow is:

Windows SMTC sessions
        ↓
SmtcMonitor (events + 2 s safety TTL)
        ↓
MediaSnapshot (immutable record)
        ↓
PresenceEngine (debounce, game mode, ignored players, artwork decision)
        ↓
ActivityFactory (templates, timestamps, buttons)
        ↓
Discord IPC (named pipe, reconnection, rate limiting)
        ↓
Discord profile

Core pieces

  • Core/PresenceEngine.cs: main loop, session selection, telemetry, game mode.
  • Media/SmtcMonitor.cs: SMTC events, session enumeration, artwork decision.
  • Core/ActivityFactory.cs: Discord activity layout and templates.
  • Tray/TrayApplicationContext.cs: tray icon, status, command polling.

Supporting services

  • Infrastructure/ListeningHistory.cs: JSONL history, summary and CSV export.
  • Infrastructure/Telemetry.cs: local CPU/memory/GC/thread sampling every 5 minutes.
  • Infrastructure/CrashDiagnostics.cs: crash bundle ZIP.
  • Plugins/PluginHost.cs: optional third-party plugins.

Artwork and program icons are cached under %LOCALAPPDATA%\UniversalPresence. Configuration and profiles live under %APPDATA%\UniversalPresence.

Build from source

Requirements

  • Windows 10 or 11, x64.
  • .NET 8 SDK.
  • Git.

Debug build

dotnet build -c Debug

Self-contained release build

dotnet publish UniversalPresence.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:DebugType=None -p:DebugSymbols=false -p:PublishDir=publish/

Run tests and diagnostics

UniversalPresence.exe --self-test
UniversalPresence.exe --test --dry-run --seconds 20
UniversalPresence.exe --list
SmartScreen. The published executable is not code-signed. Users must click “More info → Run anyway”. The code is open and can be built locally.

Atomic save and recovery

Writes use config.json.tmp, then replace config.json and keep config.json.bak. If reading fails, the app tries the backup. Secrets are written to secrets.dpapi.json with DPAPI and are never included in normal config exports.

Plugin API

Plugins are optional .NET assemblies. They receive track changes after the app builds the internal snapshot. Use them for integrations such as scrobbling, logging, overlays or custom notifications.

1. Create the project

dotnet new classlib -n MyUniversalPresencePlugin -f net8.0-windows
cd MyUniversalPresencePlugin

Reference the main project or copy the required namespaces. The plugin must target net8.0-windows.

2. Implement the interface

using UniversalPresence.Media;
using UniversalPresence.Plugins;

public sealed class MyPlugin : IUniversalPresencePlugin
{
    public string Name => "My plugin";

    public void Initialize(PluginContext context)
    {
        context.Log("Plugin started");
    }

    public void OnTrackChanged(MediaSnapshot? snapshot)
    {
        if (snapshot is { IsActive: true })
        {
            // snapshot.Title, snapshot.Artist, snapshot.PlayerName...
        }
    }
}

3. Install it

  1. Build the plugin in Release mode.
  2. Copy the DLL to %LOCALAPPDATA%\UniversalPresence\plugins.
  3. Set PluginsEnabled to true in config.json.
  4. Restart Universal Presence.

Artwork pipeline

The app tries to use the cover provided by SMTC. For browsers it makes a deliberate decision:

  • Browsers are ignored by default, so a YouTube tab is not published.
  • If the user removes a browser from the ignored list, the app checks the cover size.
  • Covers smaller than 200 px are treated as favicons and ignored.
  • Covers of 200 px or more are treated as real video thumbnails and kept.
  • TikTok is trusted when SMTC reports a real thumbnail.

The decision is cached per thumbnail so the app does not re-evaluate the same image on every tick. The chosen decision is logged as smtc, browser-ignored, browser-real, tiktok or none.

If no cover is available, the app looks it up on iTunes and Deezer in parallel. Program icons are extracted at 256 px from the player executable and cached.

Game mode

When a game runs in fullscreen, the app can pause publishing to avoid interrupting the game or exposing private content. Detection is based on the foreground window and monitor coverage:

  • The foreground window must not be the shell or desktop.
  • The window must cover the full working area of its monitor.
  • Multiple monitors are handled independently.

This logic lives in Core/PresenceEngine.cs and is evaluated during the main loop.

Profiles

Profiles allow different setups for different contexts, such as “work” and “gaming”. The default profile is config.json. Other profiles are stored in %APPDATA%\UniversalPresence\profiles\{name}.json.

  • Use the settings window to create, switch or delete profiles.
  • Use --profile name to request a switch from the CLI.
  • The active profile is stored in ActiveProfile.
  • Switching saves the current profile before loading the new one.

Localization

Presence text and UI text are separate. Presence text lives in Localization/PresenceText.cs. UI text lives in Localization/UiText.cs.

Add a new UI language

  1. Add a new UiText static field with all required strings.
  2. Add a case in UiText.For(string).
  3. Add the language to PresenceText if needed.
  4. Run --self-test to validate the build.

The current UI supports 18 languages: English, Spanish, Portuguese, French, German, Italian, Dutch, Polish, Russian, Ukrainian, Turkish, Japanese, Korean, Indonesian, Swedish, Czech, Simplified Chinese and Traditional Chinese.

Diagnostics and telemetry

Listening history

Tracks are appended to a JSONL file. The app can read, summarize and export them to CSV. History is local only.

Telemetry

Every 5 minutes the app samples memory, CPU, GC collections and thread count. The result is written to the log only; nothing is sent externally.

Crash diagnostics

If the app crashes, it creates a ZIP bundle with environment information, redacted configuration and the current log. The bundle is stored locally and can be attached to an issue.

Self-test

--self-test validates configuration roundtrip, secret protection, localization and activity generation. Run it before every pull request.

Security and updates

  • Secrets are protected with DPAPI in secrets.dpapi.json.
  • Config writes are atomic and keep a backup.
  • Updates are downloaded only when the release publishes a 64-character SHA-256 digest.
  • The downloaded file is hashed and compared before installation.
  • Auto-rollback uses config.json.bak and started.flag when startup fails.
  • The app does not send telemetry or media data to any project server.

Release process

  1. Bump Version in UniversalPresence.csproj.
  2. Bump the version in installer/UniversalPresence.iss if you ship an installer.
  3. Run --self-test and --test --dry-run.
  4. Build the self-contained executable.
  5. Commit, tag as vX.Y.Z and push the tag.
  6. GitHub Actions builds the Windows executable and creates the release.

The release workflow is defined in .github/workflows/release.yml. It publishes a single self-contained UniversalPresence.exe.

Troubleshooting

Discord does not show the activity

Make sure Discord is open and not in a restricted status. Check that the app is not paused. Run --test to see whether SMTC sessions are detected.

A player is missing

Check --list. If the player does not expose SMTC, Universal Presence cannot see it. Remove it from IgnoredPlayers if it was added accidentally.

Browser covers are wrong

Check the log for the artwork decision. Small images are treated as favicons. Remove the browser from the ignored list only if you want its thumbnails published.

Config is corrupt

The app tries config.json.bak automatically. You can also start with --config path to test a clean file.

Contributing

Contributions are welcome. Keep these rules:

  • Do not add player whitelists. Every SMTC session must remain detectable.
  • Keep the app dependency-free unless there is a strong reason.
  • Run --self-test and --test --dry-run before submitting.
  • Document new configuration options in this guide.
  • Prefer small, focused pull requests.
